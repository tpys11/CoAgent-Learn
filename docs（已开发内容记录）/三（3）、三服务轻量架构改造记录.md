# 三（3）、三服务轻量架构改造记录

## 一、改造背景与目标

原系统使用 6 个 Docker 容器：frontend、backend、redis、chroma、postgres、neo4j。比赛演示场景存在三个痛点：

1. **启动重**：6 个容器需拉取 6 个镜像（pgvector、neo4j 等大镜像），首次启动耗时数分钟；
2. **数据分散**：业务数据在 Postgres、向量在 Chroma、缓存配置了 Redis——备份/迁移/演示要导出 3 处数据；
3. **依赖冗余**：Redis 全项目零引用（纯占位）；pgvector 扩展建了但从未用于向量检索（向量实际走 Chroma）；Chroma 内置默认英文 embedding（all-MiniLM-L6-v2）对中文检索效果差。

**改造目标**：统一为 **3 服务架构**——frontend + backend + neo4j，业务与向量数据全部并入 SQLite 单文件 `app.db`。

## 二、改造后架构

```
之前:  frontend + backend + redis + chroma + postgres + neo4j  (6服务)
现在:  frontend + backend + neo4j                              (3服务)
        └── data/app.db 单文件：14 张业务表 + 2 张 sqlite-vec 向量表
```

| 组件 | 之前 | 之后 |
|------|------|------|
| 业务数据库 | PostgreSQL 12 张表 | SQLite 12 张表（同一批表，SQLite 语法） |
| 知识库向量 | Chroma 容器（英文 embedding） | sqlite-vec 内嵌向量表（中文 embedding） |
| 记忆向量 | Chroma 容器 | sqlite-vec memory_vectors 表 |
| 缓存 | Redis（零引用） | 删除 |
| 图数据库 | Neo4j | 保留（知识图谱功能不变） |

## 三、核心实现

### 1. 统一数据层 sqlite_client.py（新增）

`backend/core/sqlite_client.py` 提供 SQLiteClient 单例，关键设计：

- **接口兼容**：`execute(sql, params)` 返回 `list[dict]`，与原 pg_client 完全一致；
- **占位符兼容**：自动将 Postgres 风格 `%s` 转为 SQLite 的 `?`，全部旧调用零改动；
- **WAL 模式 + busy_timeout**：解决并发读写锁问题（主线程写消息 + 后台线程提炼记忆）；
- **sqlite-vec 集成**：`enable_load_extension + sqlite_vec.load()`，vec0 虚拟表自动建 HNSW 索引；
- **14 张表**：12 张业务表（projects/dialogues/messages/global_profile/project_memories/user_profiles/feedback/stats/resources/entities/relations/dialogue_memories）+ kb_vectors（知识库向量）+ memory_vectors（记忆向量）。

### 2. 兼容层 postgres_client.py（重写）

`from core.postgres_client import pg_client` 的所有调用（main.py 30+ 处、memory_ops、memory_analysis、graph.py）无需改动——`pg_client = get_db()` 直接指向 SQLite 单例。

### 3. 知识库服务改造（knowledge_service.py）

- **存储**：Chroma `HttpClient` → SQLite `kb_vectors` 表（project_id 过滤实现按项目隔离）；
- **向量化**：Chroma 默认英文 embedding → **bge-small-zh-v1.5**（中文模型，512 维，huggingface 镜像下载）；
- **检索链路保留**：向量检索 + BM25 关键词 → RRF 融合 → bge-reranker P3 精排（三层检索架构不变）；
- **降级策略**：embedding 模型不可用时自动降级为确定性哈希伪向量，链路不断。

### 4. 记忆存储改造（memory_store.py）

向量层 `add_vector/search_vectors` 从 Chroma 改为 `memory_vectors` 表；文本层（SQLite/SQLAlchemy）与图层（三元组）保持不变。

### 5. 清理与配置

- **docker-compose.yml**：删 redis/chroma/postgres 服务，backend `depends_on` 仅 neo4j；挂载 `../data` 持久化；
- **config.py**：删 REDIS_/CHROMA_/POSTGRES_ 配置，新增 `SQLITE_DIR`；
- **requirements.txt**：删 chromadb/psycopg2-binary/redis，加 `sqlite-vec>=0.1.6`；
- **.env**：删废弃变量，加 `SQLITE_DIR=./data`；
- **.gitignore**：`*.db / *.db-shm / *.db-wal`，运行时数据不进仓库。

## 五、后续注意事项

1. **embedding 模型首次下载**：bge-small-zh-v1.5（约 100MB）首次使用从 hf-mirror 下载，需网络；下载后可考虑挂载缓存目录；
2. **旧 Postgres 数据**：未做迁移（演示数据重建即可），如需要可写一次性迁移脚本；
3. **SQLite 并发**：WAL 模式已开启，单用户场景无感；若未来多用户并发写，需评估；
4. **Docker 依赖重装**：sentence-transformers 仍较重，容器重建慢的问题可用依赖卷挂载优化（已记录在全局建议中）。
