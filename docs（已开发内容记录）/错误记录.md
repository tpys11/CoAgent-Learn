# 开发错误记录（每次动手前必过一遍）

> 本文件记录本项目开发中犯过的错误和踩过的坑。**每次开始修改代码前，先通读一遍**，避免重蹈覆辙。

---

## 一、最高频错误（必须牢记）

### 1. `\n` 转义问题（出现 3+ 次，最致命）
- **现象**：在 Windows 上写含 `\n` 的代码到文件，字面量"反斜杠+n"被写成**真实换行**，导致 JS/Python 语法错误、前端界面崩溃。
- **案例**：DragDropInput 的 `\r\n\r\n`；renderContent 正则两次崩溃。
- **避免方法**：
  - 写含 `\n` 的代码后，**必须用十六进制验证**：`0x5c 0x6e`（反斜杠+n），而不是 `0x0a`（换行）。
  - 复杂代码用 `write_file` 生成脚本，少用 heredoc。

### 2. git checkout 丢失未提交修改（多次）
- **现象**：用 `git checkout -- .` 或 `git checkout -- <文件>` 把**做好的功能**回退了。
- **避免方法**：
  - 改代码前**先 commit 或备份**（`cp 文件 文件.bak`）。
  - 不随便 checkout，即使要回退也先看 `git diff`。

### 3. heredoc / bash 转义问题
- **现象**：`python << 'PYEOF'` 里 `\n`、引号被 bash 处理，写入文件变成错误内容。
- **避免方法**：复杂字符串改用 `write_file` 写生成器脚本；纯文本 heredoc 用单引号 `'EOF'`。

## 二、环境与依赖

### 4. Docker 容器重建丢手动装的包
- **现象**：`docker exec pip install` 装的包，容器重建后丢失（backend 镜像依赖是构建时装）。
- **避免方法**：新依赖必须**加进 requirements.txt**，需要时 `docker compose build backend`（注意 Docker Hub 网络问题，build 可能失败）。

### 5. 缺 python-multipart 导致 FastAPI 起不来
- **现象**：用 `Form`/`File` 上传文件报 "Form data requires python-multipart"，容器启动崩溃。
- **避免方法**：文件上传接口必须装 `python-multipart` 且进 requirements.txt。

### 6. Docker Hub 网络失败
- **现象**：拉取/构建镜像时 `auth.docker.io` 连接失败（代理问题）。
- **避免方法**：不依赖 rebuild，用"临时禁用路由 → 起容器 → exec 装包 → 恢复"方案；或配置镜像加速。

### 7. chromadb 连接方式
- **现象**：旧代码 `chroma_api_impl='rest'` 在新版报 "Unsupported Chroma API implementation"。
- **避免方法**：新版用 `chromadb.HttpClient(host=..., port=...)`。

### 8. Git Bash 路径转换
- **现象**：`docker cp /tmp/x` 或 `docker exec python /tmp/x` 中 `/tmp` 被 Git Bash 转成 Windows 路径。
- **避免方法**：用 `docker exec ... sh -c "python /tmp/x"`（sh -c 包裹）；或经项目目录中转。

## 三、数据库

### 9. Neo4j 全局唯一约束冲突
- **现象**：`Entity.name UNIQUE` 导致跨项目同名实体（如"元春"）写入冲突，关系全被吞。
- **避免方法**：用复合约束 `(name, project_id)` 唯一；或不用全局唯一。

### 10. 向量结果和 BM25 的 key 不统一
- **现象**：向量检索用 `md5(content)`，BM25 用 chroma uid，两者对不上导致 BM25 白算。
- **避免方法**：统一用 **chroma uid** 作为 key。

### 11. BM25 测试语料过小 idf=0
- **现象**：2 块语料时 BM25 全 0 分，误以为库坏了。
- **避免方法**：测试用真实规模语料（>10 块）。

### 12. 忘记配置项/表结构
- **现象**：config.py 缺 NEO4J 配置（被 checkout 弄丢）；dialogues 表缺 session_id。
- **避免方法**：改完配置检查 `grep`；表结构加 `ALTER TABLE ... IF NOT EXISTS` 幂等。

## 四、AI 与大模型

### 13. AI 返回非纯 JSON
- **现象**：DeepSeek 返回"好的，以下是JSON：```json {...}"，`json.loads` 直接解析失败。
- **避免方法**：写 `_extract_json`（去代码块围栏 + 取 `{...}` 部分）。

### 14. 参数不匹配
- **现象**：`update_memories` 传了"对话文本"而非 `dialogue_id`，函数读不到数据。
- **避免方法**：调用函数前核对签名与实参。

## 五、前端

### 15. useRef 初始化副作用导致 session 变化
- **现象**：`useRef((sessionStorage.setItem(...)))` 在组件重挂载时重新生成 session，发消息和查记忆不一致。
- **避免方法**：全局状态（session/项目ID）用**模块级**生成，不用 useRef 副作用。

### 16. fetch 回来时 DOM 未渲染（时序 bug）
- **现象**：`if (!chartRef.current) return` 导致 `setGraphEmpty(false)` 不执行，界面一直是空态。
- **避免方法**：目标 div **始终渲染**（提示做覆盖层），再初始化图表。

### 17. 浏览器缓存 GET 旧数据
- **现象**：图谱请求返回缓存的空数据。
- **避免方法**：fetch 加 `{ cache: 'no-store' }`，后端加 `Cache-Control: no-store`。

### 18. 项目 ID 每次刷新生成 → 数据"丢失"
- **现象**：上传的知识库刷新后查不到（项目 ID 变了）。
- **避免方法**：项目 ID 用 localStorage 固定（首次生成后复用）。

### 19. 附件卡片布局挤掉输入框
- **现象**：`w-full` 卡片在 flex 行内独占一行，textarea 被挤出。
- **避免方法**：卡片移到输入行**上方**（flex-col）。

## 六、流程与沟通

### 20. 反复让用户"刷新"测试导致误解
- **现象**：让用户 Ctrl+Shift+R 刷新，但刷新会换项目 ID，数据"消失"，用户困惑。
- **避免方法**：先想清楚"刷新会改变什么"再让用户刷新；能自己验证的用 playwright。

### 21. 让用户反复发消息测试
- **现象**：让用户发消息才能查日志，浪费用户时间。
- **避免方法**：能自己查数据库/日志/playwright 验证的，不麻烦用户。

### 22. 大改动不先 commit
- **现象**：改了一堆才 commit，中途出错难回退。
- **避免方法**：**小步提交**，每个功能完成就 commit。

### 23. 调试脚本误提交进 git
- **现象**：check_graph.cjs / verify_*.cjs 被 commit。
- **避免方法**：临时脚本放 /tmp 或 workspace，不进项目目录；提交前 `git status` 检查。

### 24. 改代码时把相邻代码弄坏
- **现象**：删 SQLITE_PATH 时把 REDIS_HOST 缩进弄坏；插入 ALTER 破坏三引号。
- **避免方法**：修改后用 `compile()`/`py_compile` 验证语法；先备份。
