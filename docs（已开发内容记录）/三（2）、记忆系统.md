# 三（2）、记忆系统

## 一、总体架构

记忆系统采用三层存储设计，由记忆管理 Agent 负责自动更新，同时暴露接口供用户手动管理。每个记忆点均附带创建时间和更新时间戳。

```
┌─────────────────────────────────────────────┐
│              记忆管理 Agent                  │
│    ┌──────────┐  ┌──────────┐  ┌─────────┐  │
│    │ 文本记忆层 │  │ 向量记忆层 │  │ 图记忆层  │  │
│    │ (SQLite)  │  │ (Chroma) │  │(三元组)  │  │
│    └────┬─────┘  └────┬─────┘  └────┬────┘  │
│         │              │             │        │
│    ┌────▼──────────────▼─────────────▼────┐  │
│    │         /api/memory CRUD 端点        │  │
│    └────────────────┬────────────────────┘  │
│                     │                        │
│    ┌────────────────▼────────────────────┐  │
│    │        前端记忆界面 / 用户手动管理    │  │
│    └─────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

## 二、三层存储详解

### 1. 文本层（SQLite）

**用途**：存储结构化的文本记忆，如学习偏好、项目上下文、诊断结果等。

**存储格式**：

| 字段 | 说明 |
|------|------|
| `id` | 唯一标识 |
| `scope` | 作用域：`"global"` 或 `"project:<id>"` |
| `level` | 层级：`"text"` / `"vector"` / `"graph"` |
| `content` | 文本内容 |
| `metadata_json` | 附加元数据（JSON 格式） |
| `created_at` | 创建时间戳 |
| `updated_at` | 更新时间戳 |

**操作接口**：`add_text()` / `update_text()` / `delete_text()` / `get_texts(scope, limit)`

**示例记忆点**：
```
id: mem-1711900000000
scope: global
content: 用户偏好理解原理优先于记忆，视觉型学习者
created_at: 2026-07-25 14:30
updated_at: 2026-07-25 14:35
```

### 2. 向量层（Chroma）

**用途**：对文本记忆生成向量嵌入，支持语义相似度检索。

**存储格式**：Chroma collection `memory_vectors`

**操作接口**：`add_vector()` / `search_vectors(query_embedding, scope, top_k)`

**使用场景**：
- Agent 在回答前检索相关记忆上下文
- "用户上次问过类似的问题吗？"
- "有哪些记忆与当前话题语义相关？"

### 3. 图层（三元组关系）

**用途**：以三元组 `(主体, 谓词, 客体)` 形式记录知识图谱关系。

**示例三元组**：
```
(LangGraph, 用于, Agent编排)
(用户, 掌握了, React基础)
(CoAgent-Learn, 依赖, FastAPI)
```

**操作接口**：`add_graph_relation()` / `get_graph(scope, limit)`

## 三、记忆管理 Agent

记忆管理 Agent 是 LangGraph 工作流的一个节点，在每次对话完成后自动触发。

**工作流程**：
1. 调度 Agent 完成所有子 Agent 调用后，传递完整上下文给记忆管理 Agent
2. 从对话中提取关键信息，分别存入三层
3. 给每个记忆点加上当前时间戳
4. 区分全局记忆（用户偏好、学习风格）与项目记忆（项目特定上下文）

**Agent 系统提示词要点**：
```
你是记忆管理 Agent。负责用户记忆的读写：
- 每次交互后自动更新记忆
- 支持三层存储（文本/向量/图）
- 提取关键事实存入文本层
- 生成嵌入存入向量层
- 识别实体关系存入图层
- 每个记忆点附带时间戳
- 区分全局记忆与项目记忆
```

## 四、用户手动管理

### 管理界面功能

| 功能 | 说明 |
|------|------|
| 文本记忆列表 | 展示所有文本记忆，每项显示内容和时间戳 |
| 图关系列表 | 展示三元组关系 |
| 作用域切换 | 全局/当前项目 切换查看 |
| 手动添加 | 输入框添加新的文本记忆 |
| 删除 | 每条记忆右侧删除按钮 |
| 自动管理开关 | 开启后 Agent 自动更新 |
| 刷新按钮 | 从后端重新拉取最新数据 |

## 五、与知识图谱的联动

右侧栏的知识图谱区域直接读取记忆系统的图层数据：
- 三元组渲染为节点和连线
- 作为知识图谱缩略图，可点开放大、拖动
- 每个节点对应记忆系统中的实体

## 六、后端 API 接口

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/memory` | GET | 获取文本记忆列表 |
| `/api/memory` | POST | 添加文本记忆 |
| `/api/memory/{id}` | PUT | 更新记忆 |
| `/api/memory/{id}` | DELETE | 删除记忆 |
| `/api/memory/all` | GET | 获取全部数据（文本+图） |
| `/api/memory/graph` | GET | 获取图关系数据 |
| `/api/memory/last-updated` | GET | 获取最近更新时间 |

### 使用示例

```python
# 添加文本记忆
POST /api/memory
{
  "scope": "global",
  "content": "用户偏好理解原理优先于记忆",
  "metadata": {"category": "learning_style"}
}

# 查询图关系
GET /api/memory/graph?scope=project:abc123

# 返回
{
  "triples": [
    {"s": "用户", "p": "掌握了", "o": "React基础", "created_at": 1711900000.0}
  ]
}
```

## 七、技术选型

| 组件 | 技术 | 原因 |
|------|------|------|
| 文本存储 | SQLite (SQLAlchemy ORM) | 轻量、零配置 |
| 向量存储 | Chroma (chromadb) | 开源、Python原生 |
| 图存储 | SQLite (三元组存在文本层) | 初期够用 |
| 时间戳 | Python `time.time()` (Unix float) | 精确、跨平台 |
| 前端状态 | React useState + fetch API | 与现有技术栈一致 |
